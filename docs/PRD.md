# 产品定义：Aily 企业智能助手

## 1. 背景与调研结论

这不是通用聊天机器人，也不是营销官网，而是面向 AI 产品经理求职演示的企业内部智能办公助手 Demo。员工需要用自然语言查制度、写周报、查一条实时信息、创建会议；面试官需要看见系统如何理解问题、选择路径、调用知识和工具、处理异常并返回可核验结果。「过程可解释」优先于「功能数量多」。

完整飞书 Aily、钉钉 AI 助理把知识、技能、工作流做成平台，过程主要放在管理员运行日志和调优台。Dify 一类对话应用接近独立 Web 聊天，引用可以挂在回答下，但员工主界面通常没有与每一轮同步的事件流，也缺少企业写操作的确认作废与超时未知状态。

竞品结论见 `docs/competitor-analysis.md`。已确认采用 **融合方案 D**：

- 气质与纪律对齐飞书 Aily：有据才答、展示引用、无依据拒答、Skill 按固定流程办事、企业工作台风
- 办事与确认对齐钉钉助理思路：技能是办事能力，写操作先确认；不搬规划技能
- 会话结构对齐 Dify：最近对话 + 中间消息流 + 引用来源
- 本 Demo 独有：员工工作台右侧是 **本轮 Agent 事件流**（按时间追加，只展示真实发生的节点），不是固定流程图；另有轻量评测与案例，用少量预置用例对照预期/实际路由和 Bad Case

优先级：**SDD 工作流 > 已确认 PRD / 产品规格 > 原型图**。原型图只作视觉布局和交互方向参考；与本文冲突时以本文为准，不得为还原图片而改业务逻辑。

本项目与 `ai_work_companion` 完全独立，不合并产品定义、代码或数据结构。

## 2. 产品目标与成功结果

- **目标用户：** 两类人共用同一演示身份（林小北｜产品部），无登录。一类是要办事的企业员工；一类是要看清 Agent 怎么做事的演示观察者（求职者 / 面试官）。
- **当前问题：** 制度分散，通用模型会编；完整企业 AI 平台过重，过程藏在后台；普通聊天 Demo 只能「聊两句」，无法演示理解、路由、引用、确认和失败。
- **产品承诺：** 员工用自然语言完成知识问答、生成周报、查询一条实时信息、创建会议。系统按固定链路处理：问题改写 → 意图 → 槽位 → 路由 → 企业知识 / Skill（编排原子能力）→ 结果核验 → 回复。有企业知识才答并给引用；写操作先确认；失败显示未知，不装成功。同一轮真实执行以事件流出现在工作台右侧，只展示实际发生的节点。
- **MVP 成功结果：** 默认林小北能现场走通 S-001～S-008：差旅制度有据问答与无据拒答、创建会议（含澄清/消歧/确认）、生成可改周报、查询明天下午 3 点以后可用的会议室、工具超时后为未知、改关键槽位后旧确认失效。评测与案例能对照少量用例的预期路由与实际路由。
- **明确不承诺：** 不是生产级 Aily；不嵌飞书、不接真实后台；不做 Planner / ReAct / Multi-Agent / 开放规划；不做登录与知识库治理；不把查询信息做成多数据源平台；不把执行任务做成会议以外的新场景；不保证全公司知识覆盖或真实日历写入。

## 3. 用户角色与权限原则

| 角色 ID | 角色 | 目标 | 当前阻碍 | 允许做什么 | 不允许做什么 |
|---|---|---|---|---|---|
| R-001 | 企业员工（默认林小北｜产品部） | 用自然语言查制度、写周报、查会议室、约会议 | 知识分散、通用 AI 会编、办事过程不可见、失败被说成成功 | 新建/继续自己的对话、提问、回答澄清、确认或取消写操作、修改生成的周报、看到本轮事件流与引用来源 | 改他人会话、上传/删除企业知识、不经确认执行写操作、在无依据时要求系统编造、开启开放式自主规划 |
| R-002 | Demo 操作者（非员工产品角色，与演示身份可相同） | 在验证台对照路由与 Bad Case，向面试官讲清 Agent 是否按设计走 | 真实产品把过程放在后台；普通聊天 Demo 没有可判定的 Bad Case | 仅通过「原型场景切换」或独立 `/demo/evaluation` 进入验证台；对照预期/实际路由、通过与否、Bad Case 分类 | 把验证台做成员工导航或业务页；在员工正常流程中展示评测字段；把预置案例当成生产评测集 |

权限原则：

- MVP 无登录。身份、部门、权限由 Mock 演示身份注入，固定为林小北｜产品部。
- 对话只属于当前演示身份。企业知识只读。写操作必须先确认。
- 员工侧唯一允许看到的过程信息，是工作台右侧**当前一轮**的 Agent 事件流，用于展示实际执行过程；不是评测对照台。
- 找人消歧只展示能区分同名者的必要信息，不展示与本演示无关的他人完整日程细节。
- 「评测与 Bad Case 对照」不是员工产品功能，不得出现在员工工作台正式导航中。

## 4. 核心业务场景与用户旅程

交互载体是工作台对话与右侧当前轮事件流。场景按业务结果定义，不按页面验收。除另注明外，角色为 R-001。

### S-001 有据企业知识问答

- **角色：** R-001
- **触发：** 要核对公司制度，例如「公司的差旅住宿标准是什么？」
- **过程：** 员工在当前对话里提问。系统理解问题后检索企业知识，只根据命中的制度作答，并给出文档名、章节和原文片段。本轮真实步骤按时间出现在事件流里；未发生的步骤不出现。
- **结果：** 员工看到可核对的答案和引用，能判断数字来自哪份制度。

### S-002 无可靠知识时拒答

- **角色：** R-001
- **触发：** 提出企业知识里没有可靠依据的问题（演示用预置问句）。
- **过程：** 同 S-001 进入知识检索；找不到可引用依据时，明确告知未找到可靠企业知识依据，不编制度、不造引用。
- **结果：** 员工得到拒答而不是假答案；事件流能看到检索后核验未通过、最终为拒答。

### S-003 用 Skill 创建会议

- **角色：** R-001
- **触发：** 「帮我明天下午三点跟张明开一个项目复盘会。」从「执行任务」进入同一条链，不另开新的办事种类。
- **过程：** 系统识别为创建会议，由创建会议 Skill 按固定业务规则补全：时间、参会人、主题、时长、会议类型。缺项则先问清楚；出现同名「张明」则先让员工选定是哪一位。必要信息齐且为写操作时，先展示将要创建的会议请员工确认。员工确认后，Skill 再调用找人、日历、会议等原子能力真正创建；创建结果要经过核验，成功才告知会议已创建。
- **结果：** 一次经确认、可核验的会议创建；事件流出现风险/权限、确认、原子能力结果与最终核验。

### S-004 生成本周周报并允许修改

- **角色：** R-001
- **触发：** 「帮我生成本周周报。」
- **过程：** 系统命中周报 Skill，按固定顺序：取本周工作消息 → 去掉闲聊 → 抽出工作事项 → 套该员工稳定偏好的模板/语言/篇幅 → 润色成周报。周报里的事实只能来自这一轮取到的工作消息。员工可以改生成结果；改完后以员工编辑版为准。
- **结果：** 一份可编辑周报；事件流能看出走了周报 Skill 及其固定步骤；闲聊不进周报。

### S-005 查询一条实时信息

- **角色：** R-001
- **触发：** 使用「查询信息」或演示问句「查询明天下午 3 点以后可用的会议室」。
- **过程：** 系统识别为只读查询，调用一条查询类能力拿到预置的实时结果并展示。不走创建会议，不要求写操作确认。
- **结果：** 员工看到可用会议室查询结果；事件流显示只读查询，不出现写操作确认。

### S-006 工具超时后不得显示成功

- **角色：** R-001
- **触发：** 在创建会议链上命中预置的超时情况（可重复进入的预置对话；验证台也可回放，但不属于员工流程）。
- **过程：** 员工已确认创建，但创建结果在约定等待内没有确定成功。系统进入未知状态，提示需要核验，不得说会议已创建。
- **结果：** 界面与事件流都是未知 / 待核验，而不是成功。

### S-007 改关键信息后必须重新确认

- **角色：** R-001
- **触发：** 已确认过的会议（例如 14:00）被员工改成另一关键槽位（例如 15:00）。
- **过程：** 旧确认立即作废，不能沿用上次同意去创建。系统用新参数再出一份确认，员工再次同意后才允许创建。
- **结果：** 不会出现「改了时间却按旧确认创建」；事件流能看到旧确认作废和新确认。

### S-008 Demo 验证：用少量案例核验路由（非员工产品场景）

- **角色：** R-002（Demo 操作者）
- **类型：** Demo Validation / Internal Demo Tool，**不计入员工侧 MVP 产品 Feature**
- **触发：** 要向面试官证明预期走哪条链、实际走了哪条、失败如何分类。入口仅为顶部「原型场景切换（非产品功能）」或独立路径 `/demo/evaluation`。
- **过程：** 在明确标注「Demo Validation / 非产品功能」的验证台查看预置案例的预期路由、实际路由、是否通过、Bad Case 分类，并可回放对应事件流。验证操作不写入企业知识，也不直接创建成功会议。
- **结果：** 能用几条案例讲清 S-001～S-007 是否按设计走；失败案例可归到超时或确认失效等类型。
- **员工侧禁止出现：** 预期路由、实际路由、通过/不通过、Bad Case 分类、评测案例列表，以及「评测与案例」正式导航。

### 场景交接

- S-001～S-007 的办事人是员工；员工只在工作台右侧看本轮事件流。
- S-008 只存在于 Demo 验证台，不是员工导航或业务页。
- 「执行任务」与 S-003 是同一条业务链；「查询信息」只通向 S-005。

## 5. MVP 范围、V2+ 与非目标

### MVP 范围

| 场景 | MVP 必须成立的业务结果 | 深度边界 | 延后内容 |
|---|---|---|---|
| S-001 | 差旅类制度问句得到带引用的答案，数字可对上制度原文 | 预置知识、单组织、中文、默认林小北 | 知识上传治理、多知识库、真实检索服务 |
| S-002 | 无可靠依据时拒答，不编造、不假引用 | 一条预置拒答问句即可演示 | 全量拒答策略运营、敏感词体系 |
| S-003 | 经澄清/消歧/确认后创建会议，成功才告知已创建 | 一个创建会议 Skill；原子能力仅找人 / 日历 / 会议 | 改会议、取消会议、复杂审批流 |
| S-004 | 生成本周周报，事实来自本轮工作消息，可被员工修改 | 预置本周消息 + 林小北稳定偏好 | 跨周汇总、多模板、真实消息拉取 |
| S-005 | 查到明天下午 3 点以后可用的会议室 | 一条只读查询能力、固定演示问句 | 多数据源、订阅、复杂分析 |
| S-006 | 创建会议超时后为未知，必须核验，不得显示成功 | 一条可重复进入的超时演示 | 重试策略产品化、人工工单 |
| S-007 | 改关键槽位后旧确认失效，必须重新确认才允许创建 | 关键槽位至少包括会议时间 | 全槽位冲突策略、多人同时改 |

员工侧 MVP 工作台：对话结果 + 当前轮事件流。无登录。正式导航只保留「对话」和最近会话，不为了页面数量增加其他导航。

S-008 的对照能力保留为 **Demo Validation Harness**，见下方，不计入员工侧产品 Feature。

### V2+

| 结果 | 延后理由 | 前置依赖 |
|---|---|---|
| 嵌入飞书或对接真实 Aily 后台 | 非演示闭环所必需 | 飞书应用权限、真实租户 |
| 真实模型 / 真实知识检索 / 真实日历 | MVP 用可替换 Mock 即可稳定复现 | 供应商、额度、数据迁移 |
| 登录与多人权限、多租户 | 演示身份已足够 | 账号与组织体系 |
| 知识上传、伙伴人设配置后台 | 与本 Demo 目标分离 | 独立产品定义 |
| 改会、取消会、审批流、日程冲突处理 | 会把「执行」做成平台 | 日历与审批业务规则 |
| 多数据源查询、订阅推送 | S-005 只需一条只读查询 | 数据源清单 |
| Planner / 开放规划 / 工作流画布 / Multi-Agent | 明确禁止 | 若未来要做需重新定义产品 |
| 千级评测集与自动回归平台 | 面试只需少量预置用例 | 标注与跑批工具 |
| 附件、深度思考、其余导航频道 | 原型有、规格无 | 新的场景确认 |

### 非目标

- 不做生产级飞书 Aily，不嵌入飞书，不接入真实 Aily 后台。
- 不做 Planner、ReAct、Multi-Agent、开放式自主任务规划、工作流画布编排。
- 不做登录、注册、多用户权限体系、多租户、组织架构管理。
- 不做知识库上传/删除/治理、智能伙伴人设配置后台。
- 不做改会、取消会、审批流、日程冲突自动改期。
- 不把「查询信息」做成多数据源平台；不把「执行任务」做成会议以外的新场景。
- 不做附件、深度思考、以及原型中未纳入 MVP 的导航（工作助手、知识库问答、会议助手、内容生成、我的任务、设置、评测与案例）。
- 不把评测对照做成员工产品页面；员工正常流程中不出现预期路由、实际路由、通过/不通过、Bad Case 分类、评测案例列表。
- 不做大规模评测集、自动标注平台、生产可观测产品。
- 事件流不做「全节点常驻的固定流程图」。
- 不与 `ai_work_companion` 合并产品定义、代码或数据。

## 6. 业务规则

| 规则 ID | 规则 | 适用场景 | 违反时结果 |
|---|---|---|---|
| BR-001 | 没有可靠企业知识依据时，不得生成制度答案，也不得伪造引用来源 | S-001 / S-002 | 拒答：未找到可靠企业知识依据 |
| BR-002 | 知识答案中的关键数字和条款必须能对应到本轮引用片段 | S-001 | 不得作为成功有据回答 |
| BR-003 | 创建会议缺必要信息（时间、参会人、主题等）时，先澄清，不得创建 | S-003 | 停留在追问，不产生会议 |
| BR-004 | 参会人存在同名时，必须让员工选定具体的人，不得擅自指定 | S-003 | 停留在消歧 |
| BR-005 | 写操作必须先展示待执行内容并获得员工明确确认，确认前不得创建会议 | S-003 / S-007 | 拒绝执行，保持未创建 |
| BR-006 | 关键槽位（至少包括会议时间）在确认之后被修改，原确认立刻作废 | S-007 | 必须用新内容重新确认 |
| BR-007 | 创建结果未在约定等待内得到确定成功时，状态为未知，禁止宣称会议已创建 | S-006 | 提示需要核验，最终为未知 |
| BR-008 | 只有核验为成功，才允许对员工说「会议已创建」 | S-003 / S-006 | 否则按未知或失败处理 |
| BR-009 | 周报中的工作事实必须来自本轮取到的工作消息；长期记忆只提供模板、语言、篇幅等稳定偏好 | S-004 | 多出来的内容不得当作本周工作事实 |
| BR-010 | 闲聊类消息不得进入周报事项 | S-004 | 过滤后不出现在周报正文 |
| BR-011 | 查询信息是只读，不走写操作确认，也不走创建会议 | S-005 | 误入写链路则拒绝按会议创建执行 |
| BR-012 | 「执行任务」与创建会议是同一业务链，不另开新的办事种类 | S-003 | 不产生第二种执行结果 |
| BR-013 | 事件流只记录本轮真实发生过的步骤；未执行的步骤不出现 | 全部 | 不得渲染成一张固定全量流程图 |
| BR-014 | 写操作的事件流必须包含风险/权限、确认、结果核验 | S-003 / S-006 / S-007 | 该轮不得视为写操作演示合格 |
| BR-015 | 对话只属于当前演示身份；不得查看或修改他人会话 | 全部 | 拒绝访问 |
| BR-016 | 评测案例只存在于 Demo 验证台：不写入企业知识，不直接创建会议，且不得出现在员工工作台正式导航或员工正常流程中 | S-008 | 拒绝当作员工功能；员工侧不展示评测字段 |
| BR-017 | 员工可修改已生成的周报正文；修改后以员工编辑版为准 | S-004 | 不得在员工改完后悄悄改回模型原文冒充终稿 |

## 7. 业务数据概念与生命周期语言

| 概念 | 业务含义 | 由谁产生 | 生命周期 |
|---|---|---|---|
| 演示身份 | 当前使用者是谁、哪个部门、读写权限；MVP 固定为林小北｜产品部 | 系统注入 | 进入工作台即存在，全程不变 |
| 对话 | 员工与助手的一次连续办事上下文 | 员工新建或继续 | 进行中；切换对话不把旧槽位带到新对话 |
| 一轮提问 | 员工的一句输入及助手为此给出的全部结果 | 员工发起 | 处理中 → 已回复 / 待澄清 / 待确认 / 未知 / 已拒答 |
| 意图 | 本轮要做的事（制度问答、创建会议、生成周报、查询会议室等） | 系统理解 | 随本轮产生；澄清后可更新 |
| 槽位 | 办事所需关键信息（如会议时间、参会人、主题） | 系统从话语提取，员工可补全或修改 | 空缺 → 已填 → 被修改（触发确认作废） |
| 路由决定 | 本轮走知识、走某个 Skill，还是走只读查询 | 系统 | 随本轮固定；评测里与预期比对 |
| 企业知识条目 | 可被引用的制度/手册片段 | 预置，员工只读 | 可用；无可靠命中则不能当答案依据 |
| 引用 | 答案所依据的文档、章节、原文片段 | 知识问答成功时产生 | 附在该轮回答上；拒答时不得出现假引用 |
| 确认单 | 写操作执行前展示给员工的待办摘要 | 系统在槽位齐后产生 | 待确认 → 已同意 / 已取消 / 已作废 |
| 技能 | 有名字的固定办事流程（创建会议、生成周报） | 预置 | 被命中后按固定步骤执行，不开放自行规划 |
| 原子能力 | Skill 或只读查询调用的单一动作（找人、查日历、创建会议、取消息、查会议室） | 预置 | 调用中 → 成功 / 失败 / 超时 |
| 事件 | 本轮实际发生的一步 | 系统随处理追加 | 按时间进入本轮事件流，结束后只读回放 |
| 周报草稿 | 本轮生成的、可编辑的周报文本 | 周报 Skill | 已生成 → 员工已修改（可选） |
| 评测案例 | 一条带预期路由和分类的演示用例 | 预置 | 只读；对照通过 / 不通过 |

## 9. 风险与约束

- 现场若接真模型，同一问句可能偏离预置路由。MVP 默认全程 Mock；真模型只能作为显式开关，不得作为验收依赖。
- 创建会议 Skill 若吸收规划或审批，会违反「不做开放规划」。Skill 只编排已确认的找人 / 日历 / 会议步骤。
- 事件流若做成固定流程图，READ 场景仍会出现确认节点，造成虚假过程。
- 超时与确认作废两条异常若共用一个不可重置的对话，第二条可能演不出来。必须提供可重复进入的预置对话或评测案例。
- Mock 身份仍代表员工，不得在界面或事件流里泄露与本演示无关的他人完整日程。
- 不得把 `ai_work_companion` 的产品定义（知识问答伙伴、禁止 Agent 办事）合进本项目。
- 后端开发须使用 Python 3.11+（SDD 约束）。当前开发机若只有 3.9，进入开发前必须具备 3.11+。
- 原型图与本文冲突时，以本文为准。

尚未锁定：无（产品定义已定稿；物理字段见 `docs/data-model.md`，接口 DTO 见 `docs/api-contracts.md`，实施见 Feature `plan.md`）。
