# F-003 用 Skill 创建会议功能规格

## 1. 功能身份

- Feature ID：F-003
- 功能名称：用 Skill 创建会议
- 所属版本：MVP
- 主要角色：员工（R-001）
- 来源需求：S-003、S-006、S-007、BR-003、BR-004、BR-005、BR-006、BR-007、BR-008、BR-012、BR-014
- 依赖 Feature：F-001
- 对应页面/视图候选：对话工作台（中栏澄清/确认/结果 + 右栏事件流）
- Spec 状态：Ready
- Spec 版本：1

## 2. 用户结果

员工用自然语言（或「执行任务」入口）走创建会议技能：补全信息、消除同名歧义、确认后才创建；核验成功才告知已创建；超时为未知；改关键槽位后旧确认作废并须重确认。

## 3. 前置条件与触发条件

- 前置条件：当前对话已存在（F-001）；预置至少两名同名「张明」可区分部门；存在可重复进入的超时演示对话或等价预置条件
- 触发条件：员工发送「帮我明天下午三点跟张明开一个项目复盘会」，或从「执行任务」进入同一条链

## 4. 功能范围

### 包含

- 创建会议技能按固定规则编排：时间、参会人、主题、时长、会议类型
- 缺必要信息时澄清，不创建
- 同名人员消歧
- 写操作确认；确认前不创建
- 技能调用找人 / 日历 / 会议等原子能力
- 核验成功才说「会议已创建」
- 原子能力超时 → 本轮为未知，禁止宣称成功
- 关键槽位（至少会议时间）修改 → 旧确认作废 → 新确认
- 「执行任务」与本 Feature 同一业务链
- 本轮事件流必须包含风险/权限、确认、结果核验等实际发生步骤

### 不包含

- 改会、取消会、审批流、自动避开冲突
- Planner / 开放式规划 / 工作流画布
- 会议以外的新执行场景
- 真实日历写入作为验收条件（预置原子能力即可）

## 5. 主流程

1. 员工发出创建会议请求（自然语言或执行任务入口）。
2. 系统命中创建会议技能；缺槽位则追问，同名则请员工选定具体的人。
3. 必要信息齐后展示确认单（时间、参会人、主题等），本轮为待确认。
4. 员工明确同意且确认单仍有效后，技能调用原子能力创建会议。
5. 核验为成功后本轮已回复，告知会议已创建；事件流追加风险/权限、确认、原子能力结果、核验。

## 6. 异常与边界流程

- 缺少时间或参会人或主题：待澄清，不出现确认后的创建成功。
- 两个张明未选定：待澄清，不得擅自指定。
- 员工取消确认单：不创建会议。
- 已确认后将时间从 14:00 改为 15:00：旧确认作废，必须对新内容再次确认。
- 命中预置超时：本轮未知，界面与事件流均不得出现「会议已创建」。
- 确认单已作废仍尝试按旧单创建：拒绝。

## 7. 业务规则与不变量

- BR-003：缺必要信息先澄清，不得创建
- BR-004：同名必须由员工选定
- BR-005：写操作必须先确认
- BR-006：关键槽位修改后原确认立刻作废
- BR-007：约定等待内未确定成功则为未知，禁止宣称已创建
- BR-008：只有核验成功才允许说会议已创建
- BR-012：执行任务与创建会议是同一业务链
- BR-013：事件流只记录真实发生步骤
- BR-014：写操作事件流必须包含风险/权限、确认、结果核验

## 8. 业务数据读写

| 动作 | 业务对象 | 业务含义 | 数据 Owner |
|---|---|---|---|
| 读取 | 技能、原子能力、演示身份 | 命中创建会议技能并找人 | 预置 / 平台注入 |
| 创建 | 一轮提问、意图、槽位、路由决定、确认单、事件 | 记录本轮写操作 | F-003 |
| 修改 | 槽位、确认单、一轮提问 | 补全、作废确认、已回复或未知 | F-003 |

## 9. 权限、隐私与安全约束

- 写操作必须确认；未确认不得创建。
- 消歧只展示能区分同名者的必要信息，不展示无关的完整他人日程细节。

## 10. 外部服务与降级边界

- 依赖服务：找人 / 日历 / 会议均为可替换 Mock 原子能力
- 完整验收需要的权限：无真实日历权限
- 缺失时允许的降级：用预置原子能力完成演示；超时用预置条件复现
- 降级时不得宣称：不得宣称已写入真实飞书/钉钉日历；超时时不得宣称会议已创建

## 11. 验收标准

### AC-F003-01 确认并核验成功后会议已创建

- Given：当前对话已打开，存在可区分的两名张明
- When：员工走完消歧与确认，确认单有效且创建核验成功
- Then：员工看到会议已创建；事件流含风险/权限、确认、结果核验
- 验证类型：agent

### AC-F003-02 缺必要信息时澄清且不创建

- Given：当前对话已打开
- When：员工发出缺少时间或参会人的创建会议请求
- Then：系统追问缺失项，不出现会议已创建，不产生已同意的有效确认单执行
- 验证类型：agent

### AC-F003-03 同名人员必须消歧

- Given：通讯录中存在两名张明
- When：员工说跟张明开会且未指定是哪一位
- Then：系统要求选定具体的人，不得直接创建
- 验证类型：agent

### AC-F003-04 未确认不得创建

- Given：槽位已齐，确认单待确认
- When：员工尚未同意
- Then：会议未创建，不得出现会议已创建
- 验证类型：auto

### AC-F003-05 改关键时间后旧确认作废

- Given：员工已确认 14:00 的会议
- When：员工将时间改为 15:00
- Then：旧确认作废，必须出现针对 15:00 的新确认；在新确认同意前不得按 14:00 或 15:00 创建成功
- 验证类型：agent

### AC-F003-06 超时后为未知且不显示成功

- Given：员工进入可重复的超时演示条件并已确认创建
- When：创建结果在约定等待内未确定成功
- Then：本轮为未知/待核验；界面与事件流均不出现会议已创建
- 验证类型：agent

### AC-F003-07 执行任务走同一创建会议链

- Given：当前对话已打开
- When：员工从执行任务入口发起约张明开会
- Then：后续澄清、确认与成功/失败规则与自然语言创建会议相同，不产生第二种办事结果
- 验证类型：agent
