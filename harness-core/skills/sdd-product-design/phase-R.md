# 阶段 R：竞品调研

## 前置条件

- 当前项目为 Web 项目
- `docs/PRD.md` 尚不存在
- 用户已提供基本的产品方向描述

## 澄清问题

提问必须覆盖：

- **用户与场景**：谁在用、什么场景、当前怎么解决的
- **核心痛点**：现有方案最大的问题
- **产品形态**：Web/移动/桌面、AI/传统
- **产品边界**：功能范围、角色权限、数据可见性、生成 / 保存 / 下载规则

不要询问数据库字段、接口设计、组件拆分、开发任务顺序等技术实现问题。

## 调研执行

充分理解后，调研同类竞品（至少 2 个，至少 1 个国内产品），输出：
- 竞品对比：关键流程、核心功能、功能取舍逻辑、视觉风格


## 产出方式

调研结论持久化为 `./docs/competitor-analysis.md`。用户确认选用方案后，关键结论写入后续的 PRD.md 背景章节。
