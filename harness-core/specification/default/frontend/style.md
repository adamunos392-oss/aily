## 设计底线

以下四节是写码时的实现要求。视觉具体值（配色/间距/圆角/字号）的单一权威源 = 已确认原型。

### 设计上下文优先

- 开写页面前先找设计上下文：已确认原型、已有组件/页面、PRD 页面描述、用户提供的截图/Logo/品牌色
- 找到上下文必须复用其中的具体值（颜色/字号/间距/圆角/组件状态），禁止凭印象改近似值
- 原型未覆盖的部分：做明确的设计假设并在输出中标注 assumption；禁止凭空做 generic UI

### 字阶策略

- 字号按信息层级递减，同一层级同一字号；标题与正文区分字重/字号，不得全文一套
- 判定：同一层级的信息出现两种字号 = 违规；标题与正文用同一字号同一字重 = 违规

### 圆角与视觉值

- 圆角、配色、间距以已确认原型为准；原型未覆盖处，同类组件全站统一一档圆角，不混用多档
- 判定：与原型不一致 = 违规；原型未覆盖处同类组件出现多档圆角 = 违规

### 布局效率

- 数据密集场景用对称等分网格（3 或 4 列），不用大小混排
- 布局保持扁平，避免深层嵌套容器
- 判定：数据展示区出现不对称混排栅格 = 违规；容器嵌套超过 3 层 = 违规

## 交互状态（五态）

- 本条是**实现代码的要求**，不是原型展示要求；消费方 = Developer（写码时实现，含 Mock 阶段页面代码）+ Tester（前端任务校验时核查）；原型产物不消费本条
- 所有交互组件（按钮/输入框/可点击项）必须用真实 CSS 伪类覆盖五种状态：可用（enabled，默认样式）/ 禁用（`:disabled`）/ 悬停（`:hover`）/ 按下（`:active`）/ 聚焦（`:focus-visible`）
- 判定：任一交互组件的样式表缺任一态对应的伪类定义 = 违规

## 布局与样式易错点

**规范说明**

- **多栏布局**：避免 `grid` / `flex` 默认等高导致某一栏内容撑高整行、破坏整体结构；工作台类页面宜固定视口高度，各栏使用 `min-height: 0` 与独立 `overflow` 滚动。
- **侧栏列表**：列表区域勿依赖会被拉伸或均分剩余高度的默认行为；列表容器应**顶部对齐**，保证从上往下稳定排布。
